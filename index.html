01 / Signature work

Three things I've built, and why they matter.

Deployment

AOTInductor: deploy PyTorch without Python.

I created AOTInductor and lead its development. It compiles an exported PyTorch model into a self-contained artifact behind a stable C ABI. That artifact can be served from C++ and stays portable across GPU architectures and PyTorch releases. It has been widely adopted for production deployment, replacing earlier generations of native deployment solutions.

PyTorch 2.0

TorchInductor: from prototype to PyTorch 2.0.

I joined TorchDynamo and TorchInductor in 2022, while they were still a prototype in a separate repo. I worked across the compiler: scheduling, op lowerings, and a long tail of codegen correctness. I also built the quality bar it shipped against: model-suite CI, accuracy checks, and PyTorch's core test suites running under Inductor. Later I built the nightly PT2 performance dashboard that tracks speedup, compile time, and memory.

See the PRs →
Runtime overhead

Taking the host out of the hot path.

I turned Inductor's C++ wrapper into a first-class mode for both JIT and AOT, removing Python from the kernel-launch path, and added lazy kernel compilation for faster cold starts. Now I'm driving CUDA Graphs and regional compilation, which give large models per-region control over how they're compiled and captured.
